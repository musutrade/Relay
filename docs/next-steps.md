# 下一步

当前先验证一个本地持久化闭环，不拆出大批规划任务。

1. **补齐故障与并发验证**：对多连接争抢、重复提交、进程重启、旧 generation 写回和边界输入保持可复现测试；先跑相关测试再扩大范围
2. **接一个最薄的外部适配器**：选择一个真实需求入口，通过库或 CLI 提交有界 payload 并读取结果；MCP 只是可选入口，业务格式不进入内核
3. **跑通开发执行器与宿主恢复**：外部执行器负责工作流，宿主确认进程树停止并处理工作区；演练“副作用已发生但结果未落库”的恢复路径
4. **用实际闭环决定扩展**：记录阻塞恢复时间、队列等待和接口缺口，再判断是否需要取消、并行或远程入口；每项扩展保留明确边界和针对性验收
