# ADR 0001：从本地持久化交接内核开始

- 状态：采用
- 日期：2026-10-03

## 背景

需求整理、开发执行和宿主资源管理各有独立责任。需要一个可恢复、可测试的交接点，但不需要先实现完整 Agent 平台或搬入已有项目的流程体系。

## 决策

1. 使用 Rust 库和轻量本地 CLI；暂不开放网络监听
2. 使用 `rusqlite` bundled SQLite 持久化状态；修改操作使用 immediate transaction
3. 仅提供提交、领取、完成、读取，以及确认旧执行停止后的重新排队
4. 一个数据库串行执行一个任务，以幂等键消除重复提交，以 owner 和 generation 防止陈旧写回
5. payload / result 保持有界、不透明的 UTF-8 文本；业务契约由外部组件解释
6. claim 不自动过期，恢复必须由可信宿主确认旧执行已停止

## 原因

SQLite 与单一状态机可以直接测试重启、重复请求和并发争抢行为，不需要预先引入服务发现、消息中间件或分布式协调。显式恢复承认内核无法判断外部执行是否真正结束，避免超时后旧、新执行并行发生副作用。

## 代价与限制

- 崩溃的执行器会阻塞同库后续任务，直至可信宿主完成恢复
- 单库吞吐受串行领取限制；本轮不增加并行分区或工作池
- 本地文件权限构成安全边界，owner 不提供认证
- 栅栏只保护内核状态，无法回滚 Git 提交、消息、支付或其他外部副作用
- SQLite 保存的文本不等于安全执行指令；目标授权和命令执行仍由外部负责

## 暂不采用

- 自动过期 lease：没有停止旧执行的可靠证据
- 分布式队列与微服务：尚无需求证明其成本必要
- 动态插件与完整工作流引擎：会把外部职责引入内核
- 全宿主输入证明与强制全量质量流程：与本轮最小交接目标无关

只有出现具体用例和可验证约束时，才重新讨论以上取舍；先验证窄接口，再增加能力。
