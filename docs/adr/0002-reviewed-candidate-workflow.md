# ADR 0002：在应用层以精确候选 SHA 约束开发交付

状态：已采纳

## 背景

旧通用命令演示的无 Git 快照适合验证队列与进程生命周期，但在发布阶段才建立提交，无法证明测试、审查和发布对应同一份交付内容。原生 CLI 的进程成功也不等于有效审查批准。

## 决定

- 不改变不透明 Rust 队列或增加业务状态；工作流、Git 与证据校验归 `relay-app`
- 工作流只引用可信配置的仓库、开发者、测试、reviewer 与 publisher，不接受 job 任意命令或参数
- 从干净本地源固定 base SHA，通过独立 Git 仓库导入；宿主在测试前提交每个 candidate
- 测试和审查后验证候选完整性。reviewer 必须使用供应商强制的只读工具配置，并返回精确 SHA 的有界结构化 verdict；提示词不构成权限边界
- 当前 Claude 受限只读路径可用；不能可靠关闭项目 MCP/hooks 的 Codex reviewer 明确拒绝，Codex 开发路径继续可用
- 修复次数默认零、最大三次，复用一个总期限；仅明确可修复结果可进入下一轮，超时、取消、非法协议或未知执行不重派
- publisher 只推送经过测试和批准的 candidate SHA，检查远端 base 一致并创建 draft。外部结果不确定时保留核对标志，不自动重复发布

## 代价和限制

需要干净源仓库，不支持子模块或符号链接。完整 diff 和工作区有界，超限失败。CLI 及机器托管设置仍属于可信部署；这不是恶意代码或多租户沙箱。CLI 实际账户和模型能力需另行验收，离线假 CLI 测试不证明认证或费用能力。远端 base 检查是观察而非锁；GitHub 副作用没有恰好一次保证。旧无 Git 通用演示保留兼容。
