# 工作区保留预览

网页“工作区保留预览”只在显式读取、刷新或翻页时请求已认证的 `GET /api/workspaces?before=<正任务编号>`，不跟随任务列表轮询。页面显示配置根内的固定 `task-N` 工作区、当前 claim 的任务 / generation / owner、共享该目录的历史续接任务，以及当前成功保留策略的观察结果。

这不是清理操作：没有删除按钮、删除接口、TTL 写入或自动清理开关。预览不授予删除权限，也不意味着目录可以安全删除。它不查询或保证 GitHub PR 合并状态。工作区文件和真正清理仍由可信宿主管理，队列内核不理解这些语义。

## 两种容量不能混为一谈

- 本页“已分配空间”来自 Linux `st_blocks × 512` 元数据，包括根目录、子目录、Git、独立 reviewer、控制文件和符号链接自身；不跟随链接目标，同一 `(device, inode)` 的硬链接在单个工作区内只计一次
- 任务容量 / 配额仍使用原有的普通文件逻辑字节，与已分配块不同；稀疏文件、压缩、reflink、快照、跨目录硬链接都可能使两者不同
- 块数不是独占占用或删除后可回收空间，也不是磁盘预留、OS 硬配额或一致性文件系统快照；不可用保持未知，不完整观察明确标记并带原因与时间

只枚举配置 `workspace_root` 下规范的 `task-N` 名称。身份无效、符号链接或缺少 claim 的目录保持未知，不递归量测；旧 `task-N-generation-M` 目录、临时 preflight、其他名字以及配置根之外的目录不属于此页的受管清单，未扫描、大小未知。页面没有任意路径参数，也不做全主机磁盘扫描。

## 当前策略与保护

现有 `successful_workspace_retention_seconds` 仍是显式 opt-in，默认关闭。页面只读取它，不改变配置或启用清理。

- `protected`：当前或后继任务排队 / 活跃、后继预留尚未提交、宿主锁被占用或不可读，或当前结果不是成功
- `unknown`：身份、持久任务与 claim 不匹配，共享链不完整 / 当前 owner 不是末端，完成标记不匹配或缺失，读取超过边界等
- `disabled`：成功及完成证明可核对，但宿主未配置成功 TTL
- `waiting`：当前成功和完成标记匹配，尚未达到 `finished_at + TTL`
- `eligible`：以上成功证明匹配，当前时间已达到既有 TTL；仅表示本次读取时符合现有策略证据，不是删除建议、执行承诺或授权

共享链的历史失败结果不会在当前 owner 后来成功后永久阻止既有成功 TTL；旧结果仍不可改写并单独显示。旧 owner 的完成标记也不能代表新 owner。预览与宿主清理共用 task / generation / owner、成功结果及 workspace 路径的完成证明检查；实际清理仍在执行时重新取得宿主独占锁并核对当前证据。

## 有界与陈旧状态

- 每页最多 16 个根，按根任务编号倒序；`next_before` 为下一页游标
- 根目录枚举最多 10,000 项及协作式 100 ms；不能完整枚举时返回不完整和原因，不伪造完整分页
- 每条续接链最多 100 个任务，使用已有 predecessor / task-key 索引，不全表扫描任务，也不返回 payload、需求或配置环境
- 一次请求在条目与链步骤间检查 250 ms 协作式预算；每次块量测沿用最多 100 ms、100,000 项或宿主更低上限、128 层和 1 TiB + 1 字节观察边界
- 协作式限制不能中断已阻塞的文件系统 / SQLite 系统调用；并发文件变化意味着完整遍历也不是静态快照
- 目录描述符锚定与 no-follow 读取避免通过路径或链接改读其他目录；锁读取不会创建或重写控制文件
- 页面错误、登出、历史恢复及较新的读取会清除或隔离旧数据；刷新前所有可见值都只是显示时间的观察

后续若需要手动清理或更丰富的保留规则，应作为独立功能设计，明确授权、保护、执行前再核对和结果审计。此增量不提供这些控制。
